## Paths

Every whackagent skill writes `{backlog}` `{tasks}` `{wiki}` `{reports}` `{conventions}` `{worktrees}` instead of literal folder. They resolve from `paths:` in config (*Config file* below), read at step 1 — project may keep wiki in `docs/wiki/` so team that doesn't run whackagent still read it.

- **Key missing → the default** (`.lunabee/agents/BACKLOG.md`, `.lunabee/agents/tasks`, `.lunabee/agents/wiki`, `.lunabee/agents/reports`, `.lunabee/agents/conventions`, `../<repo>-worktrees`). Config written before `paths:` existed keep working untouched.
- **Relative resolves from repo root**, not cwd. Absolute paths resolve, but never user-specific ones (`/Users/<name>`, `/home/<name>`, `~`) — config versioned, shared.
- **Config file** — `.lunabee/agents/config.md`, the one fixed path: it carry the others.
  - Absent, `.whackagent/config.md` present → **old layout** (project set up before `.lunabee/agents/`): stop, say `old layout — /wa-setup moves it to .lunabee/agents/ (migration 0003)`, read nothing else, move nothing. Only `/wa-setup` reads it, to run that migration. The backlog pane and `wa-backlog` stop with the same words.
  - Neither → project not set up: suggest `/wa-setup`, stop.
- Path points at nothing → say which key and what it points at, suggest `/wa-setup`. Never fall back to default folder behind user back, never create folder somewhere else: wiki silently written to default is wiki team never sees.
- **Convention modules** — `review.modules` entry `skill:<plugin>:<skill>` → rulebook shipped as skill by another installed plugin (company guidelines: `skill:lunabee-android:android-development`), loaded **by name** with Skill tool — never by file path: install location differs per machine and per install mode (user, org-managed). Any other entry → `{conventions}/<path>` (project file: whackagent module copy, or overlay of project rules on top of skill). List order = load order, **later wins on conflict**. Orchestrator hands subagents list in order: `skill:` names as is, files resolved to absolute paths — never a dir. `review.focus` entries' `modules` resolve same way, handed to verifier in `topics:`; it passes each only to that entry's focused reviewer. Check every `skill:` name is in session's skill list first; missing → stop, name plugin to install (`/plugin install <plugin>@<marketplace>`), never review without it silently.
